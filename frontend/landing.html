Architecture

How CrisisPredictor was built

We identified critical failure modes in generic AI financial chatbots and designed CrisisPredictor to solve them from the ground up.

1
LangGraph category nodes
4 category nodes — Credit/Systemic, Liquidity/Shock, Macro, Geopolitical — score all 14 factors before feeding into the final prediction node.
2
RAG-grounded scoring
A FAISS vector store retrieves each factor's historical causal relationship to financial crises, giving the LLM real evidence rather than relying purely on its training data.
3
Deterministic weighting
The LLM scores each factor -10 to +10 qualitatively. Python applies locked domain-expert weights (summing to 100) to calculate the Crisis Score mathematically.
4
Real-time API integration
Live data from FRED API (yields, spreads, jobless claims, M2), yfinance (VIX, S&P 500, gold, DXY, oil), and Tavily (tariffs, geopolitical risk).
Problems with generic AI for crisis analysis
Why generic financial chatbots fail at crisis early-warning — and how CrisisPredictor solves each one.
No structural grounding
Generic chatbots don't know the historical yield-curve inversion pattern or repo-market mechanics. CrisisPredictor's RAG document encodes this causal chain explicitly.
Hallucinated confidence
Generic tools fabricate confidence levels with no mathematical basis. CrisisPredictor's Crisis Score comes from Python, not the LLM.
Stale knowledge cutoff
General LLMs don't know this week's geopolitical developments. CrisisPredictor pulls live news on every query.

A 14-factor RAG-grounded causal chain system for financial crisis early-warning
This system tests whether a deterministic, historically-grounded multi-factor framework can provide meaningful lead time ahead of real financial crises. The underlying statistical composite score was backtested and correctly flagged all six tested historical crisis events with 197-264 days of lead time, before this RAG+LLM scoring layer was added for richer, more explainable per-factor reasoning.
